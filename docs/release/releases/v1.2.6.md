## T1. `axc` Log/Scale + Single YAML Interface

### Problem (historical)

`frame.axc.yscale: log` was not a reliable single source of truth. Users often also set layer-level
`style.norm: LogNorm` to get expected colorbar behavior.

### Shipped YAML Contract

```yaml
frame:
  axc:
    color:
      scale: log       # linear | log
      cmap: viridis
      vmin: 1
      vmax: 1e5
```

Compatibility rules in current code:

- `frame.axc.color` is the preferred interface.
- `frame.axc.color.scale` is the colorbar scale contract.
- If `color.scale=log`, runtime builds `LogNorm` when limits are positive (otherwise falls back with a warning).

### Acceptance Criteria (met in later releases)

- `frame.axc.color.scale: log` alone can drive log colorbar (when data range is valid).
- `frame.axc.color.vmin/vmax` controls color-axis lower/upper bounds.
- Vertical/horizontal colorbars choose correct axis automatically.
- Missing `ticks_position` no longer raises errors; defaults are applied.
- Manual ticks, when specified, are actually applied.
- Existing YAML using `frame.axc.color.scale: log` remains functional.
