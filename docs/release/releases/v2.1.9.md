# JarvisPLOT 2.1.9 local release closure

Status: review
Date: 2026-10-13

This records the prior **2.1.9 local source candidate**, superseded by the
maintainer-selected 2.1.10 release preparation in `v2.1.10.md`. It is not a
claim of PyPI publication or a tag. The results below were obtained with 2.1.9;
they are retained as recorded rather than relabelled as 2.1.10 measurements.

## Changes and design corrections

- Native forest reads supplied row, point and interval CSV fields; it never
  computes physics cuts, training results, means or SDs. Multiple interval
  classes, intervals-only rows, literal annotations and explicit shared ticks
  use the production validate/doctor/render paths.
- Numerical grid divisions and axis ticks are independent; normalized grid
  deduplication cannot introduce another axis tick set.
- Legend JSON cards default to STIX formulas, with DejaVu Sans as an explicit
  alternative. Cut descriptions independently select their formula font.
  MathText requires `math: true` and single-pair `$...$` formula delimiters;
  selecting a font does not itself enable parsing or an external TeX process.
- Font measurements and rendered ink use the same resolved FontProperties.
  Explicit font size governs advance and overhang, not a conflicting legacy
  size argument. TTC face extraction retains numeric weight and italic/slant,
  including explicit single-family legend overrides. Native filenames and
  ordered fallback-family lists keep native resolution.
- CLI, manuals, reports and image provenance share `jarvisplot/version.py`.
  Installed JarvisPLOT metadata wins over legacy distributions and source files;
  an uninstalled checkout alone may fall back to its VERSION file.
- SVG receives valid Dublin Core provenance rather than silently losing version
  metadata. Export retries only a backend's explicit unsupported-metadata error;
  invalid drawing and I/O errors are not swallowed. Success is logged after saving.
  PNG provenance checks avoid re-encoding complete native exports, preserve existing
  text when patching a bitmap backend, close image handles and report write failures.
- Active version documentation no longer advertises 1.4.2/2.0.6/2.1.6. The old
  analysis/reducer bridge stays frozen; existing discovery/judgement verbs
  are not incorrectly labelled missing or reimplemented as old flag aliases.
- The packaged AI README reports missing capabilities promptly, with the
  maintainer-chat / user-submitted email distinction; it never sends email.

## Release gates

- `python tools/check_release.py` checks source metadata, the live-version
  document lines and the current release note.
- `python tools/check_release.py --wheel PATH` compares installed-entry metadata,
  every Python module, schema, card and manual resource against the source.
- The publish workflow checks the release tag and distributions before upload.
  This review does not execute that workflow or publish anything.
- Linux CI runs Python 3.10–3.13, including portable native forest CLI examples.
  A macOS 3.13 job runs the complete Helvetica/TTC-specific Swiss fixtures.
  A missing requested font remains an explicit production error; tests do not
  silently replace proprietary fonts or redistribute them.
- Source distributions include VERSION, documentation, the read-only release
  checker and the native forest YAML/CSV examples. Wheels contain runtime assets.
